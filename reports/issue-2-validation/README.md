## 2. 阶段 2：页面附属与重复内容

### 2.1 做法

- **识别**：一行在至少 3 页、且至少 40% 的页上、出现在页面上下边缘带（上 16%、下 12%）的同一位置，就是页面附属。数字只在找候选时替换成 `#`；页与页之间不同的数字必须随页码递增（真正的页码），否则这一行仍按正文处理。表格行上的文字只有整条基线都是附属时才算。两份文档任一份识别出的特征对两份都生效，所以 2 页的文档和 3 页的文档判断一致（R16、R24 曾因此暴露问题，已修正）。
- **比较**：每条附属文字只比较一次，不再逐页出卡。页码变化为 Cosmetic；其他附属变化为 Review；**含金额或百分比的附属保持 Material**。只在一侧出现的附属按文字合成一张默认可见的卡，并把同一侧页边带里同样的文字（如封面上的水印）一起收入。
- **来源**：每处出现都保留自己的原文和字符来源；卡上的出现位置按钮标注侧别和页码（如 `3 · 待审 P2`），悬停显示该处原文，可逐处跳转。出现次数的差异如果超出两份文档页数之差，卡片照样显示。
- **重复表头**：同一张表在多页重复、不含数字的行，作为一组配对，不再形成“身份不唯一”的待核验组。
- 页面附属不再并入正文段落；跨页时，上一页最后一行以句号或分号结束的段落就此结束（避免段落跨页吞并下一页首段）。

## 4. 不同生成途径与浏览器精细高亮

### 4.1 不同生成器的一对 PDF（`generators/`）

`make_html.py` 写出左右两份 HTML（机队表、免赔额条款、承保份额表）和明确预期 `expected.json`（10 个事件：金额重估、两条记录金额互换、承租人改成会换行的名称、删机、中间插机、正文免赔额、HPX 份额、SLD 退出与 Corvane 以相同份额和日期加入）。`print.ts` 用两条独立途径生成 PDF：

- **Chromium 打印**（Skia/PDF，带 UMR 页眉和 `Page n of N` 页脚，3 页）；
- **LibreOffice 24.2 转换**（5 页，忽略列宽、单元格垂直居中，8 位 MSN 被逐字折行）。

`check.ts` 用两个引擎比较后核对：每个事件必须恰好落在一张正确类型、带本条记录的卡上，且没有卡把 `expected.json` 中列出的不同记录配在一起。

|---|---|---|
| Chromium | 10/10，0 处错配；另有 1 张 UMR 页面附属卡 | 10/10，0 处错配；另有 1 张 UMR 页面附属卡 |

## 6. 已知限制（试用前需知）

- **身份格序号**：身份格位置是去掉数值格后的序号；某一侧有空格或数值格时序号会移位。真实样本 0 次发生，冲突时整组待核验，不会悄悄配错。
- **范围不等于物理表**：同一标题下的多张表共用身份范围（如航空三张附表）。真实样本 0 次跨表连接；若同一飞机在一张表删除、在另一张表新增，可能显示为一张修改卡。
- **两列清单**（代码 | 名称，如条款清单）不是表格行（只有两簇），相邻清单项会合成段落：商务航空 #16、#17 的删除/新增项显示在相邻项的修改卡里，可见、可定位，但不是单独成卡。
- **类别**：没有数字和关键词的行变化（如机库飞机清单加入 M-FNKE）显示为 Review，不是 Material；保期显示为 Material，不识别为 RollForward；序数上标日期（`16th`）不解析。弯撇号改直撇号会出一张 Material 卡。
- **页面附属**需要至少 3 页、40% 页数的重复；更短的文档只能借用另一份文档的识别结果。附属变化（UMR、条码）统一为 Review，含金额的为 Material。
- **居中多行格**依赖抽取顺序上的相邻关系；如果某个生成器把居中格放在远离其行的位置，仍会脱离行（变化可见，但不挂记录）。
