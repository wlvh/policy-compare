## 改了什么

只改 `packages/compare-core/structure.ts` 和 `index.ts`，不改数据契约，不动引擎。

1. **金额、日期、注册号、条款代码不再当标题。** 仍按大写规则识别标题，但含字母数字混合词、或数字占三成以上的行除外；`2.1` 这类条目编号仍是标题。
2. **同一基线上 3 个以上明显隔开的文字簇合成一行。** 数的是"间隔大于一个字高的簇"，不是提取项数量；字符和来源原样保留。这类行标记为 `structurePath.table = "recovered_rows"`。
3. **同一页上行距超过 1.6 倍字高就另起一段。**
4. **表格行只按身份证据配对：**
   - 身份格是行里除金额、百分比、日期以外的格；首列在任一侧按行从 0 或 1 连续计数时，视为行号去掉；
   - 某格的"位置＋文字"在同一张表里两侧都只出现一次，就把这两行连起来；
   - 只连到一行的行配对，并把连接它的那一格写进 `rowKey`（界面卡片会显示）；连接互相冲突的行整组进入待核验；
   - 表格行不参与任何按相似度的配对，也不参与一对二、二对一的合并；完全相同的文字仍可直接对应。

## 对 #2 第 1 阶段代码检查四点的对应

| 检查点 | 实现 |
|---|---|
| 双向唯一 | 连接图中只有"左一行、右一行"的连通块才配对 |
| 范围正确 | 唯一性和连接都在"同一章节、同一标题"的表内计算；键包含该格在身份格中的位置，不同列的相同文字不会连起来（见测试第 9 项） |
| 冲突整体保留 | 整个连通块一起进入一个待核验组，不先配掉其中一部分 |
| 所有配对入口 | 局部联合对应、合并对应、全局相似度三个入口都排除表格行；冲突组成员标记为已用，不会从其他入口再配 |

## 复现

```sh
pnpm install --frozen-lockfile && pnpm install:pdfjs && pnpm install:mupdf
pnpm verify:core
pnpm exec tsx scripts/acceptance.ts mupdf && pnpm exec tsx scripts/acceptance.ts pdfjs
node scripts/fetch-renewal-samples.mjs --out tmp/renewal-inputs
for e in mupdf pdfjs; do for c in aviation_2024_vs_2025 bizav_2024_vs_2025; do
  pnpm exec tsx packages/cli/run.ts --engine $e \
    --left tmp/renewal-inputs/testdata/renewal/$c/left.pdf \
    --right tmp/renewal-inputs/testdata/renewal/$c/right.pdf --out tmp/$c-$e.json
  python3 scripts/renewal-triage.py tmp/renewal-inputs/testdata/renewal/$c/changes.json tmp/$c-$e.json
done; done
```

`acceptance.ts` 和 `pnpm verify:core` 会覆盖 `reports/` 下已有的报告文件，复现后请用 `git checkout -- reports/` 还原。完整比较结果见 `results/*.json.gz`，解压后的 SHA-256 记录在 `environment.json`。
