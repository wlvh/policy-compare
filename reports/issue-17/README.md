## 已实现并检查的行为

- `pnpm start:local <engine> <port>`：检查 Node 24、pnpm 10.12.1、依赖和端口，仅绑定本机，自动打开浏览器，只停止本次进程组。自动检查覆盖端口冲突、成功启动和停止后端口释放。
- 首屏静态加载提示、引擎和安全配置错误说明、失败重试；PDF.js 的首次 Worker 失败会污染本页面模块状态，因此重试重新加载页面并说明需重新选择文件，避免在同一模块状态内重复失败。
- 本站 P02/P01/E03 六个虚构 PDF 一键加载；使用说明、版本、引擎版本、维护联系提示；主动诊断仅允许版本、引擎、浏览器、阶段、错误代码。关闭任务清除文件选择、密码、搜索和文档资源。
- 独立版本路径 `/releases/<id>/`、PDF.js 相对资源、构建信息和逐文件 SHA-256、静态服务器启动校验、根入口不缓存跳转、缺失文件明确 404。应用和样例没有读取预期答案。
- Docker 指定引擎、版本和提交，固定基础镜像摘要；拒绝未提交产品源码、覆盖候选标签和覆盖既有验收目录。容器验证现在执行真实浏览器流程。
- 公共外部网址测试入口：`POLICY_BASE_URL` 配合预期发布版本、引擎和资源清单哈希；不启动或复用 Vite；报告及失败轨迹按环境/版本分目录。独立 F7 临时缓存服务器检查在外部目标验证中跳过，明确不计为 Route 测试。
- OpenShift 共用约束、local/production 参数和生成器；候选版本 Deployment/Service/路径 Route 与固定入口 Route 分开生成；按摘要固定镜像、按架构选择节点、允许平台分配 UID、只读根目录、不挂服务账号令牌，入站选择器必须由平台提供，容器默认禁止出站。未连接集群，生成器的契约检查不代表服务端接受或策略生效。

操作说明及平台交接步骤见 [部署指南](../../docs/deployment.md)。旧的 `deploy/openshift.yaml` 仅保留迁移说明，防止继续使用单版本占位模板。

2026-11-05 流程补充：在候选自动检查与镜像推送之间增加[同一候选镜像人工试用](../../docs/release-image-testing.md)。新增入口核对已验镜像并保留服务，生成独立人工检查记录。本轮入口保护、复用/重启和 4 项浏览器部署检查见[补充证据](release-image-testing-20261105/README.md)；人工与真实 OpenShift 验收仍为未评价，原失败和缺口状态不变。
