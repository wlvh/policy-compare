# OpenShift 配置完整性复查

2026-11-06。对照配置模板、`render-openshift.ts`、Dockerfile、镜像构建脚本、网页构建信息及整条部署命令复查全部 12 个字段。指南统一说明用途、值从何处取得、哪些值可自行设置、参数关系、成功标志与失败处理。

| 配置项 | 对照代码的实际作用及补充说明 |
|---|---|
| `namespace` | 资源的 `metadata.namespace`；选择或创建真实项目，不自动创建。 |
| `architecture` | 构建 `POLICY_PLATFORM` 和 Deployment 节点选择条件；推广时须与原候选一致。 |
| `host` | 候选和固定入口的 `spec.host`；DNS、内部入口、默认证书和终端信任分别确认。 |
| `replicas` | Deployment 副本整数，1–20；每版本分别占用资源，不改变浏览器内 PDF 处理。 |
| `routeLabels` | Route 标签；须满足平台真实选择器，不能据标签推断其他入口已排除。 |
| `ingressPeers` | NetworkPolicy 入站来源数组；解释同项的同时满足、数组多项的任一满足、宿主网络差异及多策略放行叠加。 |
| `platformVersion` | 生成前必需的环境记录；不升级集群，也不证明兼容性。 |
| `internalIngressController` | 生成前必需的预期入口记录；不自动绑定 Route 或实现独占，实际接收者须另验。 |
| `contact` | 构建时写入网页的维护文字；改部署参数不能改写已验镜像。 |
| `registryServer` | 部署机登录候选仓库的主机，可含端口；不是应用域名。 |
| `imageRepository` | 标签与摘要前的仓库路径；核对项目分配、推送及独立的集群拉取权限。 |
| `baseImage` | 固定摘要的 Node 24 构建/运行基础镜像；目标架构、Dockerfile 兼容性、私有仓库登录及组织批准须实际确认。 |

新增 `node scripts/check-platform.ts <platform.json>`，可在安装 pnpm 依赖前直接用 Node 24 执行。检查全部字段、未知/遗漏字段、占位值、类型、范围、标签和来源结构、仓库路径、固定摘要及四项已选环境的一致性。它不连接集群或仓库、不进行 DNS/证书核验、不证明审批或真实网络隔离。

同时修正流程依赖：私有基础镜像在构建前登录及拉取；集群默认服务账号的拉取凭据与 Docker 登录分开；更新/正式推广重新确认环境变量；参数生成拒绝另一架构、另一发布版本或未核验仓库的候选。完整 JSON 示例与模板字段在测试中保持一致。登录鉴权与自动测试对 SSO 的支持边界单独列出，没有将其虚构为已有配置项。
