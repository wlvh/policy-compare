# 审阅动作后续：预算阶段与局部编辑

本轮基于 PR #26 的 `200f0a0`，不向该分支追加提交。产品与测试提交见 acceptance.json。新增两项展示能力：将配对/整体比较预算与词级细节预算分开；按已有 textOps 突出局部编辑并提供完整上下文。没有改变 Rust 算法、生产预算或结果字段。

## 行为

- budget 表示这些范围未完成对应和比较，继续显示覆盖摘要。word_diff_budget 单独说明两侧全文保留、词级比对未完成、高亮较粗，并指导检查完整段落。卡片和导航只使用本记录自己的来源依据。
- 普通修改仅在未改文字的语句边界省略远处上下文；全部编辑组保持默认可见，币种、否定词、条件所在原句不按字数裁切。长句完整显示。省略会明确提示并提供完整两侧文本；操作串不足时退回全文，不伪造精确高亮。
- 查看提示可返回原选中编辑组、筛选和清单滚动位置。显式 Review changes 与来源定位将文档工作区带入视口；辅助工具有组合空间约束，卡片仍保有阅读区域。查看不登记为已核实。
- AGENTS.md 与现有验证说明补入发现、理解、定位、返回及结果保留的通用验收要求。

## 证据

初版四项浏览器回归在 PR #26 旧预览上为 3 失败、1 通过：旧配对预算文案为通过对照，另外三项暴露了词级文案、局部编辑和完整审阅动作的缺口。之后补强了返回同一编辑组、清单位置及实际窗口尺寸断言。

本轮也修正了测试自身的窗口设置：新建页面必须逐页 setViewportSize，并断言 innerWidth/innerHeight；不能把默认窗口结果当作较矮窗口证据。早期未生效的窗口设置和开发失败记录仍保留在本地中间目录，不能作为短窗通过证据。此处提交的两份最终报告均来自显式 1280×800 的实际操作页。

- 单元与合同测试 479/479，新增 5 项，包含实际 WASM 小预算对照、所有编辑保留、长句、Unicode 与操作串不足回退。
- 两种构建、全项目类型检查通过。MuPDF、PDF.js 各 19/19 受影响浏览器检查通过；新增 4 项与原提示、重复来源、扫描覆盖/搜索/导出等回归同行。
- 操作流程：选择第二编辑组 → 定位两侧实际修改 → 搜索 → 展开重复来源 → 打开提示并定位 → 返回原编辑组和清单位置 → 继续下一处修改。
- 普通量 4 条和大量 48 条观察作关系对照；两侧正文可见宽度大于 200、高度大于 250 像素，清单高度至少 150 像素。这些是目标场景的保护条件，不等同于所有分辨率、字号或设备上的人类可用性验收。
- 新增一对明确标注的合成 PDF，产品不读取其作者预期；两处编辑按独立作者坐标检查实际两侧 SVG 来源，不从比较结果反推预期。样本及复现方法见 tests/fixtures/review-flow。
- 浏览器预算与布局记录通过测试消息注入，以验证展示；实际预算机制另由 WASM 小预算测试验证。注入不证明这些 PDF 在正常预算下会耗尽预算或有相应结构问题。
- 新测试进入默认回归与镜像入口；原外部测试、原数据集预期未修改。
