# 保单比对工具执行包

本包用于让开发代理直接开始实现。完整方案是本轮唯一的执行基线，已经纳入高敏感度、浏览器性能、本地调试、服务器部署边界，以及规则生成验证集。

## 推荐执行方式

优先使用本地 Codex。将本目录放入目标项目目录，在该项目中启动 Codex，把 `START_HERE.zh-CN.md` 的指令完整粘贴进去。没有应用仓库时，可先建立一个空的本地 `policy-compare` 目录再放入本包。

若使用云端 Claude Code，先确保本包作为仓库文件或会话材料真实可用。云端可以完成实现、自动测试和 Linux 构建；将同一提交拉回目标电脑，补浏览器和设备性能验收。不要同时开启两条独立实现主线。

## 文件入口

| 文件或目录 | 用途 |
| --- | --- |
| `IMPLEMENTATION_PLAN.zh-CN.md` | 完整实施方案：架构、契约、算法、性能、评分、任务与完成标准。 |
| `START_HERE.zh-CN.md` | 可直接粘贴给开发代理的启动指令。 |
| `validation/` | 已生成的规则验证集、64 份 PDF、标准答案、生成和构造检查工具。 |
| `validation/dataset/CASE_CATALOG.zh-CN.md` | 32 条规则的逐条目录。 |
| `validation/REVIEW_GUIDE.zh-CN.md` | 验证集的阅读与验收说明；执行冲突以完整实施方案为准。 |
| `validation/qa/` | 已检查的页面接触表；逐页中间渲染不在交付包中。 |
| `PACKAGE_MANIFEST.json` | 文件清单、SHA256 和交付状态，便于核对传输完整性。 |

本包不包含已经实现的比对产品。`pnpm dev` 等是实施方案要求最终交付的命令，不能在只有方案的目录里直接运行并期待产品存在。

## 已有成果

规则集 seed 为 20261026，共 32 对、64 PDF、130 页。样本构造检查通过，全部页面经过渲染检查。26 个普通必须发现事件、1 个金额必须可见但身份允许待复核的事件、2 个图像覆盖提示事件，以及 6 对无业务变化控制用例。

其中 R25 的 `must_detect=false` 不表示跳过：`must_detect_text_delta=true`、两侧金额和原文链接仍是必需。产品评分器应按 `detection_requirement` 执行。

规则集没有执行实际比对引擎，也没有验收浏览器性能。产品评分器、长文档性能工作负载、真实样本与目标设备验收均属于后续实施任务。

## 运行现有样本构造检查

在 `validation/` 目录，使用 Python 3.10 或更高版本：

```bash
python -m pip install -r requirements.txt
python fixture_checks.py
```

需要重建样本时执行 `python generator.py`，之后再次运行构造检查。字体及其许可随包提供。新 seed 产生同规则变体，不能代替真实留出样本。

## 执行边界

本地开发与测试可以持续推进，不逐阶段等待确认。实际许可、真实数据、凭据、外部网络、平台部署或参考设备缺失时，标记受影响的步骤并继续独立工作。不要把缺失条件写成已经通过；不要降低标准答案迎合产品输出。

当前范围完成后停止扩展，交付给用户试用。远端 PDF 计算服务、OCR、LLM、通用表格、搜索平台和桌面安装器不自动进入本次工作。
